# Foot v9：方向相关的落脚区域

> 历史版本说明：当前增量配置为 [v10](wf_zero_hold_swing_v10.md)。v9 已完成训练；以下验证状态记录实现当时的情况。

更新于 2026-09-19。在 v8 上仅新增落脚区域事件惩罚、诊断与可选 MuJoCo 可视化；v8 的步态、两档净空和零轮速参考保持。尚未训练或验收新策略。

## 目标区域

每只脚在计划摆动开始时分别确定区域，在世界坐标中锁定直到本次摆动结束，不随之后的机身移动、命令或步频变化追着脚移动。

1. 用当前命令的恒定机体系平移与 yaw 角速度，按 SE(2) 积分预测落地时机身位置和朝向；剩余摆动时间来自当前相位及步频。
2. 以预测机身为参考，叠加该脚正常站位 `(0, ±0.17 m)`。
3. 添加半个支撑周期的期望足端运动量；转向包含 `vx_i = vx - wz*y_nominal_i`，不是左右脚共用同一个前后落点。
4. 增加 `0.10 s*(v_actual_xy-v_command_xy)` 平衡修正，每个方向限制在 ±4 cm；前后相对偏移限制在 ±25 cm，左右偏移分别限制在 `[0.12,0.28] m` 与 `[-0.28,-0.12] m`，避免中心交叉。
5. 投影到局部支撑平面，生成沿预测航向的椭圆，前后/左右半轴为 **4/3 cm**。

零命令时靠近正常站位，允许有界平衡修正；前进/后退、左右侧移和左右转向产生对应目标。不是强制左右脚前后镜像，也不是强制两脚每步并齐。

## 第一版的地形与可达性范围

优先针对平地与连续缓坡，使用 121 点扫描的局部平面：

- 平面有效，坡度≤20°。
- 有效扫描点相对平面的最大法向残差≤1.5 cm；明显起伏、台阶边缘先跳过评分。
- 区域中心及四个椭圆极值点均须在有效扫描点的 8.5 cm 范围内。
- 预测机身到目标轮心的距离加最大半轴≤0.90 m，并限制上述左右/前后偏移。

这是**保守几何范围检查，不是完整逆运动学、关节限位求解或台阶边缘规划**。不把区域强行放到无扫描或明显不平整处；整块区域不可靠时跳过，不尝试裁出复杂地形上的小片交集。复杂地形筛选留待后续版本。0.90 m 是当前可调的粗略范围，应结合机构和回放验证。

## 有效离地与落地事件

实现：`FootholdRegionTracker`（纯 PyTorch，训练/部署预览共用），训练适配器为 `FootholdRegionPenalty`。

- 曾经接地支撑后，才能为一次摆动准备评分；出生时腾空直接落下不算有效迈步。
- 当前地形过滤接触力≥10 N 判接触，≤5 N 判无接触，中间保持原状态。
- 实际无接触且轮缘净空≥1 cm 连续 60 ms，才确认离地。
- 此后连续接触 40 ms，确认落地；位置冻结在这一段稳定接触的第一帧，避免后续滑移改变落脚位置。
- 每次计划摆动最多结算一次。接触抖动不重复发奖励；长时间腾空不能沿用更早周期的支撑记录反复准备评分。
- reset 清空对应环境全部历史；同一个控制步重复调用 reward 不推进状态。

没有离地/落地事件时本项为零；并不代表步态正确。原有摆动卸载、净空和支撑接触奖励继续负责建立实际迈步。

## 评分与 dt

实际轮心位置与目标地面中心的差，在目标平面两个切向轴上投影；轮半径沿法向的偏移不影响这两个分量。

```text
rho = sqrt((dx/0.04)^2 + (dy/0.03)^2)
excess = max(rho-1, 0)
event_cost = min(Huber(excess), 5)
```

区域内 rho≤1 不罚；区域外扣分。`pen_foothold_region.weight=-0.2`，是**每次有效落地的成本系数**。例如 rho=2 时，单次落地贡献为 −0.1；封顶每脚每次 −1.0。两脚同一步有效落地时成本相加。

RewardManager 仍统一乘 dt，但适配器返回 `sum(event_cost)/step_dt`，因此抵消该项的 dt 缩放。不能将此权重直接与每步密集奖励比较。不对接触次数发正奖励，不添加摆动过程中的落脚点追踪项。

## TensorBoard

新训练使用短标签：

| 标签 | 含义 |
|---|---|
| `Reward/pen_foothold_region` | 落地区域惩罚贡献，日志仍受 episode 统计归一化 |
| `Foothold/landings` | 已评分的有效落地数量 |
| `Foothold/inside_rate` | 有效落地中 rho≤1 的比例 |
| `Foothold/rho_mean` | 有效落地的归一化距离均值 |
| `Foothold/plans` | 计划区域数量 |
| `Foothold/invalid_rate` | 计划区域被地形/几何过滤拒绝的比例 |
| `Foothold/missed_swings` | 下次计划摆动开始时，上次已准备摆动仍未确认落地的数量 |

零落地样本时 inside_rate/rho_mean 显示零，必须结合 landings 判断，不能解释为跟踪良好。终止/reset 步与现有 Foot diagnostics 一样不计入这些新增统计。

## MuJoCo 可视化

在原测试命令末尾加：

```bash
--show-footholds
```

- 青色椭圆：左脚目标区域；橙色：右脚。
- 绿点/红点：最近一次有效落点在区域内/外。
- 终端打印 `[foothold] ... side=L/R rho=... inside=...`。
- R 重置同时清空区域和事件历史。

优先读取 checkpoint 的 `params/env.yaml` 中 `pen_foothold_region.params.tracker_options`；旧 checkpoint 没有该项时明确提示预览当前默认参数。预览不改变策略、控制器或训练奖励，也不能让旧模型自动学会新目标。只在 Foot 且显式启用参数时计算/绘制。

训练和预览共用区域/事件核心。MuJoCo 用自身地形射线、接触力与轮下局部平面作为输入，两种物理引擎的接触观测不保证逐帧相同。

## 验证

145 项 CPU 回归通过；包括前后/侧移/转向、世界平移与 yaw 变换一致性、无效扫描/陡坡/不可达高度、目标锁定、独立 reset、首次落地与接触抖动、无离地不评分、出生腾空不评分、事件成本对 dt 不敏感、确认后沿用首次接触位置、诊断计数、适配器重复读取与 dt 抵消。

MuJoCo 旧 v7 模型完成 2 秒 headless 链路检查，以及 4 秒前进回放和离屏绘图；这些只验证代码及显示，不是 v9 策略验收。预览图：`agent_docs/temp/foothold_region_v9/preview.png`。没有启动新训练或完整 Isaac Lab/PhysX smoke。
